# 把想法讲清楚

一个面向不会写代码用户的 Codex Skill，用来把模糊想法整理成别人能理解、AI 能执行、自己能验收的需求说明。

## 适合什么时候用

- 想法还很模糊，但希望先整理清楚
- 想把需求讲给 AI、开发者、设计师、剪辑师或协作者听
- 想减少“边做边改”带来的返工
- 想把一个软件、工具、内容、工作流或项目想法变成可执行方案
- 想写轻量 PRD、Spec 或验收清单

## 核心原则

默认用户不会写代码，也不熟悉产品或工程术语。这个 skill 不要求用户先给技术方案，而是帮助用户把自然语言整理成：

- 背景
- 使用场景
- 当前问题
- 理想状态
- 约束条件
- 可执行需求
- 风险与边界
- 验收清单

## 触发方式

可以这样对 Codex 说：

```text
用“把想法讲清楚”帮我整理这个需求，先不要执行。
```

或者：

```text
把这个想法讲清楚，整理成轻量 PRD 和验收清单。
```

## 输出形式

默认输出“想法澄清稿”：

```md
## 需求重述

## 背景与使用场景

## 当前问题

## 理想状态

## 可执行需求

## 不做什么

## 风险点

## 验收清单

## 下一步
```

如果需求更复杂，可以升级为：

- 轻量 PRD
- 可执行 Spec
- Given/When/Then 验收用例

## 一个例子

原始想法：

```text
这个录屏工具摄像头不好用，每次都要调。
```

澄清后：

```text
用户希望在 Windows 上录制带摄像头画面的教程视频。选择摄像头后，画面应立即显示，支持移动和缩放；开始录制后继续显示；导出成片中应包含且只包含一个摄像头画面；关闭重开后摄像头设备、位置、大小和麦克风选择保持上一次设置。
```
