# 把想法讲清楚

把用户接下来给出的模糊想法整理成“别人能理解、AI 能执行、用户能验收”的需求说明。

默认用户不会写代码。不要要求用户提供技术方案，也不要马上实现。先澄清：

- 背景
- 使用场景
- 当前问题
- 理想状态
- 约束条件
- 可执行需求
- 不做范围
- 风险点
- 验收清单

如果需求复杂，再升级为轻量 PRD 或可执行 Spec。验收清单必须包含具体操作步骤，避免“功能正常”这类空话。

不要把模糊想法直接当成执行授权。不要替用户编造预算、平台、目标用户、时间线、技术方案或验收标准。

如果需求涉及删除数据、自动发消息、付款、公开发布、隐私信息或账号权限，必须列出风险和需要用户确认的暂停点。
